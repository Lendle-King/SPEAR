# SPEAR: executable parameter-intervention validation

**Research status:** 2026-10-30 mechanism prototype, **not** an experiment on Qwen3.5-4B, AndroidWorld, AppWorld, or an actual long-horizon LLM agent. All numerical scores in this directory are from a deliberately simple synthetic parameterized model with deterministic state checkers. Do not use those scores as evidence of LLM performance, conference-level novelty, or RSI.

## What is implemented

| Question | Executable test | Important limitation |
|---|---|---|
| G1: Does evidence change *future parameter-update payoff*? | Resettable toy environment; teacher/docs/probe observation; paired parameter-candidate validations; no-evidence and two-candidate-search controls | Evidence accuracy is generated by a known synthetic distribution; interventions are scalar weights |
| G2: Is the optimal intervention conditional on evidence? | Opposite hidden causes matched on visible error **and every pre-query metadata field**, with signed parameter-update reversal; learned PI-VOI vs fixed/random/global/type/ready rules | Reversal is constructed by design; strong rule may match PI-VOI |
| G3: Is improvement durable and old skill protected? | Numeric parameters committed to a new `Student` object; independent validation and heldout rollouts with no teacher message; checker rejects shared-weight interference | Orthogonal toy parameters and explicit rollback do **not** prove realistic LLM retention |
| G4: Does learning the improvement mechanism help? | Sequential phase0/phase1 source-quality change; fully frozen meta-model vs refitted direction and evidence-value models with **identical available replay archive** | A controlled nonstationary toy test, not autonomous recursive self-improvement |
| External evidence audit | JSONL ingestion of **actual external runner** paired outcomes, checkpoint hashes, reset seeds, split isolation, technical errors and heldout evidence | Only audits supplied records: does not train adapters, run real agents, or certify that supplied logs are authentic |

The trainable student has two numerical weights (`Student.new_weight`, `Student.old_weight`). Each new skill uses held-out inputs `x ∈ {-1, +1}` and a hidden sign mapping. Before evidence, all cases show the same error. There is a genuinely different optimal **weight update** for latent-opposite instances, despite identical pre-query observations. Teacher/probe provide signed recommendations; document evidence reports **forbidden** actions and requires the opposite sign. Evidence quality varies with *public* readiness fields and a phase-1 drift. A simulated LoRA-like constrained intervention chooses a direction, then validates it with strict checker rollouts; successful changes persist as a numeric checkpoint without re-injecting evidence.

**Important:** a source query plus one candidate validation is compared to a no-query **two-candidate exhaustive search**, since cheap validation can eliminate the need for source queries. Source and validation costs below are arbitrary synthetic utility units, not actual GPU-hours or API dollars; we disclose both validation counts and training collection costs. All methods share the collected training dataset; reported net test utility does *not* amortize meta-training collection or compute.

## Run with Python standard library only

From the **repository root**, Python 3.10+:

```bash
python -m unittest discover -s experiments/parameter_voi/tests -v

python -m experiments.parameter_voi.run \
  --seed 42 --train 360 --test 240 \
  --meta-train 240 --meta-test 240 \
  --out results/parameter_voi_cpu
```

Outputs:

- `summary.json`: split manifest, data-collection cost accounting, source-policy and static-rule comparisons, matched-pair bootstrap intervals, synthetic retention/reversal tests, and the frozen-meta comparison.
- `phase0_trials.jsonl`: every policy/world held-out record (paired on case and reset seed).
- `recursive_trials.jsonl`: frozen and adapted meta-policy records on the **same** stage-1 held-out worlds.

The tracked [`results/synthetic_seed42_summary.json`](results/synthetic_seed42_summary.json) and [`results/interpretation.md`](results/interpretation.md) are a **toy smoke run**, not a new LLM result. CI regenerates the raw JSONL artifacts for download, tests data invariants, and reruns the experiment.

## Experimental isolation and instrumentation

1. Generate paired worlds with identical visible errors and metadata but latent-opposite update directions; *latent truth is never supplied to the learner*.
2. Split paired worlds **before** fitting a direction predictor, source-value estimator, and final test results. Direction target labels come from **paired validated candidate parameter changes**, not from reading the hidden sign.
3. A second disjoint development split learns expected net payoff for each source from the selected *parameter intervention* and its held-out rollout, not from explanation-likelihood or diagnostic classification accuracy.
4. Evaluate all policies on an untouched world split. Source observations are queried at most once per policy-world. The old-skill and new-skill checker is deterministic, and final evaluation **never queries** the teacher/docs/probe.
5. Record source calls, candidate checks, rollback reasons, persistent numeric weights, checkers, old-skill loss, cost, and all method denominators. Bootstrap by **matched world pair** (not by repeated tasks within a pair).
6. Phase1 changes source reliability. Expose the same new randomized replay examples to frozen and adaptive meta-policy arms; only the adaptive arm refits the meta-components. Re-evaluate both on untouched phase1 worlds.

The demonstration has purposely simple actions and an extremely favorable oracle-style validation checker. Consequently, the exhaustive two-candidate search can get **100% synthetic task success**, but it pays twice the intervention-validation cost. Any PI-VOI cost advantage disappears if candidate evaluation is cheaper than the arbitrary cost ratio used here. This needs real empirical measurement.

## From toy controls to a Qwen3.5-4B / AndroidWorld result

The CPU scripts are a falsification pilot. The actual paper-grade experiment still requires a real runner and **training different LoRA candidates from the same frozen Qwen3.5-4B starting checkpoint**. Do not treat the CPU stage as sufficient.

For each eligibility-qualified failure: snapshot the exact model, emulator/tool state, task description, and observed trajectory. Randomize acquisition between teacher diagnosis, documentation retrieval, controlled probe and no evidence. Store the evidence message with source provenance and the known propensity. Build at least two counterfactual update candidates plus no-update from the **same** original checkpoint; train with a fixed adapter budget; run paired validation with strict checker and old-skill audits. Only commit validated updates. Evaluate the committed checkpoint on **different held-out tasks without injected teacher/search text or a temporary per-case adapter**. Run frozen-meta and adaptive-meta arms with the same logged archive, compute, and task distribution.

The prior GUI/CURE experiments showed simple observable-state conditions could explain routing performance. Therefore a pre-registered **strong rule using all fields visible to the learned router** is mandatory. A learned router that only matches that rule fails G2 for scientific novelty; do not enlarge the router to hide the result.

### Audit real runner outputs

`external_audit.py` consumes strictly paired **real external results**, not synthetic case-generator logs. An input record represents one pre/post intervention comparison and must contain:

```json
{"run_id":"actual-run-001","group_id":"skill_family_01_world_03","split":"test","policy":"pi_voi","source":"docs","source_propensity":0.333333,"visible_failure_id":"tool_error_generic","pre_checkpoint_sha":"base-sha","post_checkpoint_sha":"adapter-sha","candidate_sha":"candidate-a","environment_snapshot":"android-reset-xyz","pre_seed":39,"post_seed":39,"baseline_success":false,"candidate_success":true,"baseline_old_success":true,"candidate_old_success":true,"source_cost":0.12,"validation_cost":0.2,"accepted":true,"heldout_no_evidence":true,"episode_done_pre":false,"episode_done_post":true,"status":"complete"}
```

Replace the illustrative content with actual checker outcomes and immutable checkpoint/environment IDs. `group_id` must not cross splits. For technical errors, all four checker outcomes must be `null` and `accepted=false`; **unknown is not failure**. An accepted change must have a different checkpoint hash, while a rejected candidate must roll back to the baseline hash. On held-out evaluation, `heldout_no_evidence` must be true. `episode_done` is a separate field from strict checker success; strict success cannot occur when the episode is incomplete.

```bash
python -m experiments.parameter_voi.external_audit /path/to/real_pairs.jsonl \
  --output /path/to/real_audit_report.json
```

This validator computes paired checker and cost deltas, old-skill degradation, counts of technical errors, and *only* compares policies for groups with the same reset seed. **It is not proof of random assignment, counterfactual identification, or a reproducible LoRA training run**; attach the raw source action, training log, checker evidence, and environment provenance to your publication artifact.

## Interpreting gate outcomes correctly

- Passing source-reliability simulation tests merely establishes the **implementation is internally coherent**.
- The *actual G1* needs a real model where external evidence changes post-update held-out outcomes beyond extra gradient/data/compute.
- The *actual G2* needs **within-matched-observation** source choice / parameter direction reversal and an advantage over a strong same-input rule with confidence intervals excluding an unimportant effect.
- The *actual G3* requires persistent, held-out **full episodes** without temporary teacher context and measured retention in an agent with overlapping parameter abilities.
- The *actual G4* requires significantly better meta-learning efficiency on later skills **after charging all meta-training and search costs**, compared to frozen strategies with the same memory growth.

**Do not label all gates passed based on this repository's synthetic demonstration.**
